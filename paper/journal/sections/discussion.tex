\section{Discussion and Reproducibility}
\subsection{Reproducibility}
Files and decompressed cache content have SHA-256 manifests. Dataset identity,
feature version, protocol hash, source hash and run configuration accompany each
result. Local station reconstruction is audited independently of derived caches.
A clean-clone measured-dataset reconstruction passed its semantic hash audit under the recorded runtime. A complete primary reproduction remains pending. Numerical values
in this skeleton are generated from evidence artifacts, never filled manually.


\subsection{Limitations and Planned Completion}
ADS setup is complete. Incomplete archive coverage and primary experiments block the genuine CAMS comparison. Partial station acquisition, current-catalogue survivorship,
unknown historical observation latency and limited extreme-event support bound
the preliminary analysis. Optional fire release time remains unproven. The
initial station-free prospective forecasts do not establish station forecast
skill. Final-test isolation, transparent artifacts and explicit missing results
are necessary conditions for completion, not evidence of improved accuracy.
The intended completed narrative is CAMS baseline, India-specific correction,
rolling/spatial testing, calibrated uncertainty, cohort advisory trade-offs and
prospective station verification.


\subsubsection{Artifact lineage and release boundary}
The reproducibility package binds the protocol hash, measured semantic hash,
operational request manifest, GRIB checksums, derived table hash and feature
version. Raw files are stored outside Git, while manifests and implementation
are versioned. Resumption polls existing request identifiers before submitting
new work. Hash failures stop processing instead of replacing evidence in place.
The development reader applies its date exclusion before materialising
outcomes. The readiness report itself reads artifact metadata and hashes file
bytes; it does not run an estimator or open final labels.

Production validation and scientific validation answer different questions.
The released interface has route, API and browser checks, while the proposed
station correction still requires completed development experiments. A
successful web deployment is not a substitute for predictive validation.
Similarly, a compiled manuscript is a presentation artifact and cannot
release a research gate. A selected model, if justified later, will need a
committed feature and parameter lock, uncertainty and advisory configurations,
and a complete evidence audit before final-test authorization is requested.
